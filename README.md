# Social Book

Лента постов с комментариями по макету [Social Book (Figma)](https://www.figma.com/design/p4jDYcwlRsEVihOixcleWQ/Social-Book?node-id=1-4).

**Демо:** https://olpest66.github.io/social-book/ <!-- ссылка заработает после включения GitHub Pages -->

## Что умеет

- Добавить пост; пустой текст не отправляется, поле подсвечивается.
- Раскрыть комментарии поста кнопкой «Комментарии» и спрятать кнопкой «Спрятать».
- Добавить и удалить комментарий; счётчик в свёрнутой карточке обновляется сразу.
- Изменить пост в модальном окне: «Подтвердить», «Закрыть», `Esc`, клик по фону, `Ctrl/Cmd + Enter`.
- Удалить пост; вместе с ним удаляются его комментарии.
- Посты и комментарии сохраняются в `localStorage` и переживают перезагрузку.

## Стек

React 19, TypeScript, Redux Toolkit 2, React Redux 9, Vite, CSS Modules, Vitest, шрифт Montserrat из `@fontsource` (без внешнего CDN).

## Архитектура

Проект разложен по слоям [Feature-Sliced Design](https://feature-sliced.design/). Слой импортирует только слои ниже себя, каждый слайс отдаёт наружу только свой `index.ts`.

```
src/
├─ app/        стор, глобальные стили, провайдер
├─ pages/      feed — единственная страница
├─ widgets/    post-feed (лента), post-card (карточка: собирает сущности и фичи)
├─ features/   create-post, edit-post, delete-post, toggle-comments, add-comment, delete-comment
├─ entities/   post, comment — модель (слайс, селекторы, типы) и презентационный UI
└─ shared/     ui-кит (Button, TextField, TextArea, Card, Modal), утилиты, типизированные хуки стора
```

### Хранилище

```ts
RootState = {
  posts:              EntityState<Post>     // { ids, entities }, новые сверху
  comments:           EntityState<Comment>  // отдельная коллекция, связь через postId
  editPost:           { editingPostId: string | null }
  commentsVisibility: { expanded: Record<postId, true> }
}
```

Решения и почему так:

- **Нормализация через `createEntityAdapter`.** Комментарии не вложены в пост, а лежат отдельно и ссылаются на него через `postId`. Обновление одного комментария не пересоздаёт объект поста, и карточки не перерисовываются зря.
- **Все изменения — через экшены слайсов.** Экшены: `postAdded`, `postUpdated`, `postRemoved`, `commentAdded`, `commentRemoved`, `editStarted`, `editCancelled`, `commentsShown`, `commentsHidden`. `id` и дата создаются в `prepare`, поэтому редьюсеры остаются чистыми функциями.
- **Экшены как события.** На `postRemoved` реагируют сразу три слайса: комментарии каскадно удаляются, модалка закрывается, раскрытое состояние сбрасывается. На `postUpdated` модалка закрывается сама. Компоненту не нужно диспатчить цепочку экшенов.
- **Доменные данные отдельно от UI-состояния фич.** В `localStorage` сохраняются только `posts` и `comments`.
- **Побочный эффект — в `listenerMiddleware`.** Запись в `localStorage` вынесена из редьюсеров.
- **Мемоизированные селекторы.** Комментарии группируются по постам один раз через `createSelector`. Карточка получает стабильную ссылку на массив `id`, а лента подписана только на `ids` постов.
- **Черновики полей ввода — в локальном `useState`.** Это состояние формы, а не приложения, так рекомендует [Redux Style Guide](https://redux.js.org/style-guide/#avoid-putting-form-state-in-redux). В стор попадает только готовый текст через экшен.
- **Типы стора без импорта из `app`.** Типы `RootState` и `AppDispatch` объявлены глобально в `app/store/global.d.ts`, поэтому нижние слои их видят, не нарушая направление зависимостей.

## Вёрстка и адаптив

- Цвета, размеры шрифтов и отступы сняты с макета (кадр 1440 px, контент 800 px) и вынесены в CSS-переменные в `app/styles/index.css`.
- **Десктоп и планшет.** Ширина контента — `min(800px, 100% − 32px)`. Строка действий в карточке переносится, когда кнопкам не хватает места, а не по фиксированному брейкпоинту.
- **Мобильный (≤ 600 px).** Мобильной версии в макете нет, поэтому она сделана по своему решению:
  - плотнее отступы и меньше шрифты;
  - «Изменить»/«Удалить» и кнопки модалки растянуты на всю ширину;
  - поля ввода 16 px, чтобы iOS Safari не зумил страницу при фокусе.
- Проверено на ширинах 320–1920 px: без горизонтальной прокрутки и без наложения элементов.
- **Доступность:**
  - модалка с `role="dialog"`, ловушкой фокуса и возвратом фокуса на кнопку, которая её открыла;
  - `aria-expanded` у кнопок комментариев;
  - видимый `:focus-visible`;
  - учтён `prefers-reduced-motion`.
